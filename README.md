# NetScope X

NetScope X is a Windows desktop network monitor built with Tauri 2, Rust, React and TypeScript. The window uses a fixed **405 × 720** portrait layout.

## What the data means

- **Interface throughput and totals** are derived from Windows network-interface byte counters. Rates begin after two samples establish a real counter delta.
- **Adapters and sockets** are enumerated from Windows. If Windows cannot return them, the application reports the failure rather than inventing interfaces.
- **Per-process traffic** comes from the Windows Kernel-Network ETW collector when the session is active and Windows grants permission. When it is unavailable, the UI explicitly marks attribution as unavailable.
- **Connection latency** is a TCP connection handshake to the destination's port 443 (or an explicitly supplied host and port); it is not an ICMP Echo ping. Current, average, min/max, jitter and failed-probe percentage use actual observations.
- The **TCP/UDP mix** counts observed TCP connections and UDP endpoints. It is not a percentage of bytes transferred.
- The **History** tab stores measured hourly interface samples in a local SQLite database. The configured retention period prunes records older than the cutoff.
- Application block/unblock uses actual Windows Firewall rules for a live process executable. Windows may request administrator approval.
- The application creates one native Windows system-tray icon. Minimize, hide, restore, startup registration and exit use native Tauri/Rust commands.

The normal browser preview does not have Windows telemetry and therefore does not invent demo measurements. Use the packaged Windows app for live network data.

## Development

Install Node.js 22 or later and a stable Rust toolchain with the Windows MSVC target on a Windows development machine.

```powershell
npm ci --legacy-peer-deps
npm run lint
npm test
npm run build
npm run tauri:dev
```

For a production Windows package, install the Tauri v2 CLI and run:

```powershell
npm run tauri:build
```

## Release policy

A GitHub Release is not generated by these development changes. The manual Release workflow requires an explicitly supplied release tag; create or publish a version only after release approval.
